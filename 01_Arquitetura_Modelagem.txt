3. MODELO CONCEITUAL E LÓGICO DO BANCO DE DADOS (Supabase/PostgreSQL)
---------------------------------------------------------------------

3.1 Modelo Conceitual (Entidades e Regras de Negócio)

• ENTIDADE CONTA (herança por tabela separada — padrão Supabase Auth):
  - auth.users (tabela nativa do Supabase) armazena credenciais (email/senha).
  - profiles_usuarios e profiles_ongs espelham os dados públicos de cada tipo de conta.
  - Regra: CPF único para usuário; CNPJ OU CPF único para ONG (campo documento_ong aceita ambos, validado por regex no front e CHECK no banco).

• ENTIDADE ENDEREÇO:
  - CEP é a chave de localização. Estado/Cidade/Bairro são denormalizados na própria conta para permitir filtro rápido (LIKE + índices btree) sem JOIN pesado.

• ENTIDADE PROJETO (ONG gera 1..N projetos):
  - Cada projeto pertence a exatamente uma ONG (FK ong_id).
  - Status: rascunho | aberto | encerrado.

• ENTIDADE FORMULÁRIO DINÂMICO:
  - Um projeto tem um formulário ativo (config JSONB com array de campos: label, type [text|select|textarea|number], required, options).
  - Optamos por JSONB em vez de tabelas normalizadas de campos para flexibilidade real de formulários dinâmicos (padrão industry practice para builder de forms).

• ENTIDADE INSCRIÇÃO (APPLICATION):
  - Relacionamento N:N resolvido entre Usuario x Projeto com atributos (status, resposta_formulario, parecer_ong, data_inscricao).
  - UNIQUE(usuario_id, projeto_id): cidadão não pode se inscrever duas vezes no mesmo projeto.
  - Ciclo de vida: pendente -> aprovada | rejeitada (transições controladas por trigger).

• ENTIDADE GALERIA:
  - 1..N imagens por ONG, ordenáveis, armazenadas no Supabase Storage (bucket 'galeria-ongs') com URL pública.

3.2 Modelo Lógico (Tabelas, Tipos e Constraints)
(O DDL completo com RLS e Triggers está no arquivo 02_Supabase_Database.sql)

TABELA: profiles_usuarios
  id UUID PK REFERENCES auth.users(id) ON DELETE CASCADE
  nome_completo VARCHAR(120) NOT NULL
  whatsapp VARCHAR(20) NOT NULL
  cpf CHAR(11) NOT NULL UNIQUE (somente dígitos)
  email VARCHAR(255) NOT NULL
  rede_social VARCHAR(140) NULL
  cep CHAR(8) NOT NULL
  estado CHAR(2) NOT NULL
  cidade VARCHAR(80) NOT NULL
  bairro VARCHAR(80) NOT NULL
  bio TEXT NULL (max 300 chars via CHECK)
  foto_url TEXT NULL
  criado_em TIMESTAMPTZ DEFAULT now()
  atualizado_em TIMESTAMPTZ DEFAULT now()

TABELA: profiles_ongs
  id UUID PK REFERENCES auth.users(id) ON DELETE CASCADE
  nome_ong VARCHAR(120) NOT NULL
  telefone VARCHAR(20) NOT NULL
  rede_social VARCHAR(140) NULL
  documento VARCHAR(18) NOT NULL UNIQUE (CPF ou CNPJ formatado)
  cep CHAR(8) NOT NULL
  estado CHAR(2) NOT NULL
  cidade VARCHAR(80) NOT NULL
  bairro VARCHAR(80) NOT NULL
  bio/finalidade TEXT NOT NULL
  publico_alvo TEXT NULL
  foto_url TEXT NULL
  verificado BOOLEAN DEFAULT false
  criado_em / atualizado_em TIMESTAMPTZ

TABELA: projects
  id UUID PK
  ong_id UUID NOT NULL REFERENCES profiles_ongs(id) ON DELETE CASCADE
  titulo VARCHAR(140) NOT NULL
  descricao TEXT NOT NULL
  area VARCHAR(60) NOT NULL  -- ex: Educação, Saúde, Direitos Humanos
  vagas INT CHECK (vagas > 0)
  status project_status ENUM ('rascunho','aberto','encerrado') DEFAULT 'aberto'
  prazo_inscricao DATE NULL
  criado_em / atualizado_em

TABELA: custom_forms
  id UUID PK
  project_id UUID NOT NULL UNIQUE REFERENCES projects(id) ON DELETE CASCADE
  estrutura JSONB NOT NULL  -- {"campos":[{"id","label","type","required","options"}]}

TABELA: applications
  id UUID PK
  usuario_id UUID NOT NULL REFERENCES profiles_usuarios(id) ON DELETE CASCADE
  project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE
  respostas JSONB NOT NULL
  status app_status ENUM ('pendente','aprovada','rejeitada') DEFAULT 'pendente'
  parecer_ong TEXT NULL
  inscrito_em TIMESTAMPTZ DEFAULT now()
  decidido_em TIMESTAMPTZ NULL
  UNIQUE(usuario_id, project_id)

TABELA: galleries
  id UUID PK
  ong_id UUID NOT NULL REFERENCES profiles_ongs(id) ON DELETE CASCADE
  storage_path VARCHAR(255) NOT NULL
  legenda VARCHAR(140) NULL
  ordem SMALLINT DEFAULT 0
  criado_em TIMESTAMPTZ DEFAULT now()

ÍNDICES DE PERFORMANCE:
  idx_projects_localizacao ON projects(estado_sede derivado via JOIN) — aplicado como índice funcional em profiles_ongs(estado, cidade, bairro)
  idx_applications_status ON applications(status)
  idx_apps_usuario ON applications(usuario_id)
  idx_projects_ong ON projects(ong_id)
  GIN index em custom_forms.estrutura para busca de campos

Observações de arquitetura:
- Páginas autenticadas carregam js/core/auth.js primeiro (guard: sem sessão → redirect login.html).
- Separação role-based: pastas /usuario e /ong só acessíveis pelo tipo de conta (claim no JWT + checagem nas tabelas profiles).
- Nenhum framework: módulos ES6 (import/export) com <script type="module">.
